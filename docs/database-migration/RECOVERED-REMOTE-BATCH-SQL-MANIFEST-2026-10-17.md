## Recovery source and interpretation
The SQL payloads below were read directly from the live production project's `supabase_migrations.schema_migrations.statements` array, paired with the live `version` and `name`. Each recovered file was fetched back from this GitHub branch and compared byte-for-byte with the ledger's joined statement payload; all 35 files matched. These are forensic source records under `docs/`, deliberately outside `supabase/migrations/` so they are not automatically treated as replayable migrations.

The live ledger also records `created_by` (the same account for all 35) and `idempotency_key` (NULL for all 35). It does **not** expose a deployment timestamp, request/response ID, migration API event, or rollback payload for these entries. Thus the SQL payload and applied-ledger membership are authoritative; exact deployment time and API request/result remain unproven.
